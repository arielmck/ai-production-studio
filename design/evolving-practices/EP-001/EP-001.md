# EP-001 — AI Agent Capability, Routing, and Collaboration

Status: Proposed Evolving Practice

Current Standing Rules: none.

## Core Question

How should the Production Studio use and combine AI agents to produce
increasingly robust, maintainable code increasingly quickly?

## Goal

Use each agent where it is currently strongest, in the combination, sequence,
and constraints that currently work best, so the Studio produces code that
works reliably, addresses fundamental causes rather than accumulating patches,
remains easy to maintain and refactor, avoids fragile complexity, and creates
fewer defects and less rework while becoming faster and faster to produce within
each project. As agent capabilities evolve, the resulting lessons should also
improve how later projects are produced.

## Evolving Context

AI agents, coding tools, and the surrounding software-development industry are
changing rapidly. The relative strengths, weaknesses, best sequencing, and
useful constraints of individual agents are therefore temporary conclusions
rather than permanent truths. This Evolving Practice continuously incorporates
new evidence and revises its current synthesis and Current Standing Rules when
capabilities or better combinations change.

## Evidence

The synthesis below summarizes what accumulated pilot evidence currently
suggests, including the Agent Capability Evidence Ledger, which is not kept in a
Studio repository. Individual dated ratings and case narratives stay with that
evidence rather than in this EP.

## Current Provisional Synthesis

As of 2026-10-01. These are current evidence-backed observations, provisional
rather than permanent agent rankings.

- Claude currently appears especially useful as the first substantial
  repository investigator/implementer. Observed strengths include strong initial
  comprehension, detailed forensic reconstruction, coordinated implementation
  across existing owners, and generally easy continuation from analysis into
  implementation.
- Claude has repeatedly shown a tendency to begin designing a new mechanism
  before fully discovering existing owners, analogous solved cases, reusable
  code, or reusable concepts. A technically sound initial proposal may therefore
  still be larger than necessary.
- Codex currently appears especially useful as an independent challenger,
  particularly for reuse discovery, ownership and architecture challenge,
  provider/application semantics, counterexamples, state/failure-contract
  analysis, abstraction-boundary problems, and finding cheaper existing
  implementation shapes.
- Codex is not inherently the minimal-solution agent. It can also overengineer
  through retries, recovery, validation layers, fallback machinery, generalized
  robustness, or excessive proof.
- Claude and Codex both tend, once they identify a real failure, to move toward
  engineering protection around the failure. Both therefore need an explicit
  challenge asking whether the fundamental defect itself can first be corrected
  or prevented.
- Recovery, retry, salvage, patching, fallback, and generalized defensive
  machinery should not become the default merely because they are technically
  robust.
- ChatGPT currently adds distinct value by comparing the agents rather than
  being confined to one agent's framing; challenging whether proposed machinery
  should exist at all; identifying user agreements, human prerequisites,
  refusals, deliberate non-automation, and simpler supported boundaries; and
  protecting the distinction between correcting the root defect and recovering
  afterward.
- ChatGPT also has a recurring weakness: a detailed and persuasive Claude or
  Codex analysis can cause it to accept the diagnosis and proposed remedy
  together as one package without independently challenging necessity, reuse,
  root cause, or the human/machine boundary strongly enough.
- ChatGPT has also sometimes carried an agent's solution framing forward too
  quickly instead of reopening the cheaper question: what is the smallest
  worthwhile result?
- These conclusions describe current observed behavior. New versions, new
  agents, new tools, and new evidence may change them quickly.

## Current Provisional Working Model

A working decision model, not yet permanent policy or a Current Standing Rule.

1. For substantial repository work, Claude is currently often a productive
   first agent because of its combination of initial comprehension, detailed
   investigation, communication, and integrated implementation ability.

2. Use Codex independently when architecture, reuse discovery,
   provider/application semantics, state/failure behavior, abstraction
   boundaries, or a proposed new helper/file/state mechanism could materially
   benefit from challenge.

3. Codex's role is not merely to confirm Claude. Useful questions include:
   - What assumption is wrong?
   - What existing owner, code, concept, or analogous solved path was missed?
   - What state or failure case has not been considered?
   - Is the proposed mechanism larger than necessary?
   - Can something be removed rather than added?

4. Before adopting either agent's remedy, ChatGPT independently challenges:
   - Is the defect itself established?
   - Are diagnosis and remedy being incorrectly treated as one conclusion?
   - Does the proposed change correct the fundamental cause rather than recover
     after it?
   - What existing code, concept, owner, proof pattern, or solved case can be
     reused?
   - Can a user agreement, human prerequisite, clear refusal, bounded
     unsupported case, or deliberate non-automation eliminate machinery?
   - What new permanent responsibility does the solution create?
   - Is the proof proportional to the actual changed invariant?
   - Is another agent's independent challenge likely to save more
     implementation/rework than it costs?

5. Once the mechanism and boundaries are settled, return the work to the agent
   currently best suited to implementation; current evidence often favors Claude
   for coordinated implementation across established owners.

6. Treat the sequence itself as provisional. Do not convert today's
   Claude/Codex/ChatGPT arrangement into permanent Studio architecture.
   Reevaluate as capabilities evolve.

## Current Provisional Decision Tree

- Need substantial first-pass repository understanding or integrated
  implementation?
  → Currently consider Claude first.

- Does the work involve a proposed new helper, owner, state mechanism, recovery
  path, architecture choice, provider/application behavior, or uncertainty
  about existing reuse?
  → Consider an independent Codex challenge before implementation.

- Has either agent proposed retries, recovery, fallback, patching, generalized
  defensive machinery, substantial new proof, or a new durable owner?
  → ChatGPT independently challenges root cause, reuse, human
  prerequisites/refusals, and whether the machinery should exist.

- Did Codex or Claude find a smaller existing mechanism or better-supported
  direction?
  → Prefer the smallest worthwhile result, then use the implementation agent
  best suited to carry it through the established owners.

- Is evidence weak, conflicting, or changing because agent/tool capability has
  changed?
  → Keep the conclusion provisional and gather more evidence rather than
  promoting it into a rule.

- Has repeated evidence made a practice useful enough to follow for now?
  → It may become an Active Evolving Practice or a dated Current Standing Rule,
  while remaining explicitly revisable.

This decision tree is not automated routing or mandatory workflow machinery.
